# TASK-057 安全境界と異常終了の検証

057では、異常な入力や処理の停止が、結果の消失・秘密の流出・無制限の実行につながらないかを確かめます。既存の試験を受入条件に対応付け、不足していた試験だけを追加します。製品の検出仕様・暗号判断・出力形式は変更しません。

## 追加した試験

| 対象 | 確認すること |
| --- | --- |
| 秘密の伏せ字 | 行または列が不明でも合成秘密を伏せ、同じ文字列が公開情報なら残す |
| ファイル読み取り | 親ディレクトリをsymlinkに差し替えても、ルート外の対照ファイルを読まない |
| hard link | 通常ファイルとして読めるが、サイズ上限は守る。元の所在までは判別できない |
| 異常終了 | Rustの合成プログラムを使い、成功・捕捉したpanic・エラー・signal・時間切れ・CPU上限を区別する |
| 後始末 | 時間切れで子孫プロセスも止め、それまでのログと後続の結果を残す |
| 静的scan | 依存情報にURLが含まれても、そのURLを取得せずにレポートを生成する |

位置不明の秘匿試験は、045で見つかった試験不足にも対応します。ただし045の当時の変異スコアは書き換えません。

## 既存試験との対応

合成秘密を、ソース・秘密鍵のマーカー・依存先URL・所見のメタデータ・移行手順・コード例・参照URL・TLS/SSH観測へ入れる既存試験を再実行します。JSON、HTML、Markdown、SARIF、CycloneDX、CSV、native inventory、診断と標準エラーへの経路を対応表に記録します。英日両言語と、シリアライズ失敗時に任意のエラー本文を漏らさない試験も含めます。

ファイルの上限超過・FIFO・symlink、probeの名前解決・許可CIDR・固定IP・中止・絶対期限は既存の製品試験を使います。外部の診断対象には接続せず、偽の名前解決とloopbackの対向を使います。

## 隔離と測定の範囲

工具の準備と対象の実行を分離し、既存の固定イメージを使います。対象実行は外部ネットワークを切り、非root、読み取り専用ソース、メモリ・PID・作業領域・時間の上限を設けます。実際にメモリ不足、ディスク上限、fork上限、時間切れを起こし、コンテナーの削除まで確認します。

入力ごとの監督処理はCPU時間・ログサイズ・実時間を制限し、同じprocess groupの子孫を停止します。別のgroupへ離脱する子までprocess groupだけで閉じ込める仕組みではありません。子孫全体の資源と最終的な後始末は、外側のコンテナーが受け持ちます。終了コード42と86は試験用workerの取り決めであり、任意の製品がそのコードで終わったらpanicや検証違反と推定するものではありません。

静的scanでは、設定したloopbackのURLへの接続が発生しないことと、外部ネットワークを使えない環境でも処理できることを確認します。全てのsocket呼び出しを追跡した測定ではありません。

Linux arm64で全体を検証し、macOS arm64では追加した秘匿・ファイル試験を確認します。Windowsの実行確認はしていません。hard linkの出所、同時書き込みの一貫したスナップショット、全ての競合順序は保証しません。パス・IDや、秘密の構文として認識できない任意の符号化文字列も秘匿契約の対象外です。

## 結果と証拠

Rust 1.93.1、Linux arm64で、通常539件・全機能有効590件が成功しました。全機能構成の既存1件は実行対象外です。両構成のclippy・buildとfmtは終了コード0、Python品質試験69件、ホスト・kernel境界試験10件も成功しました。元ソースの前後一致とコンテナーの削除を確認しています。

リンク競合の試験は、レビューを受けて初回の差し替えで同期し、置換回数と通常読み取りの対照を確認するよう補強しました。また、macOSで停止済みのgroupへ二度目の停止信号を送ると試験側が失敗したため、再送を避けています。初回のイメージ設定キーの誤りも含め、開発中の失敗ログを保存し、製品の不具合と区別しています。修正後の全体検証は成功しました。
