# v0.5 frozen measurement and compatibility protocol

This protocol precedes new-language subject observations. It applies unchanged to baseline `7e8cd91426fa21609a91c0511de44252eaa890d4` and final v0.5 worktree. Main-agent-authored synthetic cases are conformance controls, not independent population truth, calibrated detection accuracy, a human usefulness study or cryptographic execution tests. The earlier routing draft and implementation source were exposed to the author; this is disclosed rather than called blind validation.

## Frozen inputs and interpretation

`evidence/CORPUS-CASES.json` specifies byte expressions, canonical family/parameter identity, reference/request/unknown boundaries and prohibited interpretations. Expressions are the focal assertions: other explicitly written calls in setup can independently yield observations. A negative focused receiver does not erase its valid constructor observation. Comments must yield no source API observations. All emitted observations remain syntactic/referenced; the expectation's request/reference describes source intent, not a new output field or successful execution. Cases are intentionally parseable partial programs with synthetic identifiers, not compilable cryptographic applications or valid keys.

`DEPENDENCY-MATRIX.json` owns literal input expectations and source editions. Unsupported editions must be visible, not a silently Complete empty result. Each format has a positive and unrelated/dynamic/unsupported control. Additional adversarial inputs are allowed as supplemental controls; do not rewrite this frozen population to hide a failure. Correct a truth error through a retained amendment showing old/new values and reason, never overwrite observations as if they preceded implementation.

`old-seven/` holds eight pre-existing source files covering Java, Go, JavaScript (positive and negative), TypeScript, Python, Rust and Ruby. `saved.inventory.json` is the exact previously accepted 075 synthetic input. Baseline and source hash indices bind actual bytes; baseline expectations are observed compatibility goldens, not independently authored new-language truth. Existing custom-pack/public-API and migration/context regressions are also required by tasks 077-083; these corpus controls do not replace the workspace or feature suites.

## Observation procedure

1. Same host and pinned Rust 1.93.1, default workspace features, dev profile, default rules, one scan worker, default limits, same input paths and explicit repository scope `v05/frozen`. Record host, OS, compiler, feature configuration, binary SHA-256, HEAD and modified source hashes. Rebuild before each phase. If environment changes, report a new stratum and rerun the comparable baseline rather than pool incomparable runs.
2. Run one warmup then three sequential measured runs per old-seven, new-source, new-dependency and saved-input group. Record exact argv, wall time, process exit, macOS `/usr/bin/time -l` raw peak RSS/resource output and output bytes per file. Native timing includes process startup and report generation, excludes compilation. Resource units are host-specific bytes on this macOS host; retain raw output and do not generalize to another OS. No hard numeric performance gate is invented.
3. Use scan `--threads 1 --format all --diagnostics --inventory-json --repository-scope v05/frozen`. Saved input uses `assess --input-format inventory-v1 --as-of 2026-11-24T00:00:00Z` and never rescan or fetch a provider. Save every exit/result, including failure. Native corpus output at baseline is unsupported/lexical context and is not new-language passing evidence.
4. Report per-group input file/byte denominator, run count, each wall/RSS/size value and median/range. No summation of per-run peak RSS. Freeze hashes and all baseline output artifacts before adopting new subject code. Final observations use a separate directory.
5. Compare old source findings by rule, original location, masked evidence, risk and safe metadata; compare inventory by normalized assets and observation-to-asset semantics. New rulepack digest/run/observation IDs and generated timestamps are expected derivations, not stable equality keys. Enumerate exact differing fields; do not blanket-strip keys or claim unchanged output with unexplained differences. Held saved input must produce equal semantic technical facts/decisions under the same catalog, context, policy and evaluation instant. Byte-input binding remains exact; stale context must fail.

## Required boundary controls in dependent tasks

Routing includes `.C`/`.c`, all listed C++ suffixes, common and conflicting `.h` facts under a shared budget, PHP-tagged/untagged `.inc`, mixed HTML and Blade partial state, C# ordinary/file-scoped namespaces, local global-using vs cross-file unknown and malformed UTF-8/syntax. Preserve original UTF-8 byte/code-point coordinates and repeated same-line calls. Scope/reassignment/import shadows and dynamic selections must not become definite bindings.

For each affected cap use below/at/above values plus zero, including shared C/C++ candidates, node/depth/alias traversal, matches, retained bytes, dependency depth/records/values and selected-file bytes. Keep current limits rather than invent larger limits to make examples pass. Test hostile headers, malformed XML/JSON, URL/key canaries and encoded/oversized values. Inspect native inventory, legacy findings, all report formats, exports and context artifacts; raw arguments/keys/URLs must not leak through new normalization. Failures/Partial/Unknown prevent dependent completion when an original required case is unmet.
