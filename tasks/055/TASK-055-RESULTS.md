# TASK-055 検査範囲と処理結果の集計

055では、pqc-scanが「何ファイルを選び、何ファイルを読めて、どこまで検査できたか」を確かめました。046の生成試験で使う統計の意味を先に固定するための作業です。製品の公開出力や判定を増やさず、既存の診断APIと実検出器から開発用の記録を集めます。

## 何を確かめるか

| 要求 | 検証内容 |
| --- | --- |
| Q2-01 | 選択数＝読み取り成功＋失敗、読み取り成功数＝各処理結果の合計。1ファイルを二重に数えない |
| Q2-02 | 公開する入力形式と対応版・未対応版を実検出器で確認する。所見0件を安全や検査成功に読み替えない |
| Q2-03 | ファイルサイズ、検出件数、候補数、探索ノード数、照合バイト数の境界を確認し、打切りと完了を分ける |
| Q2-04 | 設定された除外方針と、実際に列挙して除外したファイルを分ける |
| Q2-05 | 作成した全入力の一覧と、選択・除外・未列挙を照合する。任意のリポジトリの未知総数は不明のままにする |
| Q2-06 | 形式ごとに5検出器の適用・非適用・未報告・未対応・部分・打切り・失敗を集計し、想定した結果と比べる |
| Q2-07 | 列挙率・適用率・完了率の分母を分け、分母が不明または0なら率を作らない |
| Q2-08 | 読み取り失敗、壊れた入力、一検出器の失敗があっても、他の所見と診断が残ることを確認する |

## 入力と方法

制御した8ファイルでは、完了・部分・打切り・失敗・未対応・対象外・未報告・読み取り失敗を1件ずつ試します。ファイルごとの結果と、一括実行した結果を照合します。読み取り失敗はテスト用の読み取り関数で発生させ、権限や実行ユーザーによる偶然に依存させません。別の検出器が失敗する場合にも、正常な検出器の所見が残ることを確認します。

除外の検証には、全9ファイルが分かっている専用の一時ディレクトリを使います。通常ファイル、サイズ上限ちょうど・超過、Markdown、画像拡張子、docs配下、.git配下、ignore対象を含めています。未知のリポジトリにも総数9を当てはめるわけではありません。

実形式の検証では74入力に5検出器を適用します。依存マニフェスト・lock・SBOMの文書化された版、7言語とTSX、7系統の設定、PEM/DER/PKCS#12、合成の秘密鍵マーカー、未対応版、破損・暗号化・混在コンテナーを含めます。入力バイト列とハッシュ、固定した証明書評価時刻、各検出器の想定結果を保存します。対応する構文の例を確認するもので、全構文や実際の暗号利用を保証しません。

集約は`tests/quality/inspection055.py`で行います。欠けた検出器、重複、入力ハッシュ不一致、別入力の結果、矛盾する件数を拒否します。検出器の呼び出し数はファイル数とは別です。初回の期待値の誤りや検証失敗も保存し、成功した記録で上書きしません。

## 分母と不明情報

制御入力では、適用を確認できた4件を読み取り成功7件と比較します。失敗した適用対象も含め、確認できた適用対象4件のうち解析完了した1件を完了率の分子とします。適用不明の1件は別に残します。この率は既知の制御入力の集合に対する値で、不明な入力も含めた実製品の適用率ではありません。

任意のリポジトリについては全ファイル数を知らないため、列挙率の分母と率をnullにします。未対応、未報告、失敗、打切りを、成功や安全の件数に足しません。
