# v0.5 user-documentation applicability protocol

Reassess the original expanded-v2 applicability after simplifying COVERAGE EN/JA.
Keep the corpus, truth, labeling records, adjudications, scorer, splits and history
unchanged. This is source-based, output-exposed applicability review, not blind
truth labeling, independent population accuracy or release approval.

Each of two fresh authors reads all 203 original bounded inputs and all 246
nominal questions against the four current contracts in SOURCE-BINDINGS.json.
Use tests/quality/expanded-v2/{corpus.json,truth.json,PROTOCOL.md,provenance.json,
labels-a-width.json,labels-b-width.json}, the input files and the current four
contracts. Inspect source and public binary structure only; never execute,
import, build, install, decrypt or export key/certificate payloads from specimens.
Keep observations separate from confirmed execution or deployed use. Check
comments, strings, namesakes, shadowing, dynamic values and finite provenance.

The six historically nominated encrypted-inner questions x154,x156,v2-audit4,
v2-audit5,v2-audit6,v2-audit7 are candidates to confirm from source, not a target
number to force. Outer container references and readable public certificate
attributes remain separate. Review every other nominal positive, negative,
unsupported and ambiguous unit as well. Preserve original question/nominal labels
and explain each retained/excluded applicability from actual source structure.

Authors must not open any old applicability review-main.json/review-independent.json
or another author's current outputs. Each writes only to its assigned private
evidence directory, with one sanitized file audit per input and unit audit per
question, then freezes its review with actual identity, assigned model, timestamp,
exposure disclosure, current contract/corpus/truth/protocol hashes, dispositions,
remainingUnitsReviewed=true and unresolved decisions. otherApplicabilityReviewSeen
must reflect actual access; do not set it false after seeing another review.
The parent alone compares the frozen independent records and resolves differences
from source without rewriting either author's original identity or decisions.

The reviewer knows nominal labels and historical output exposure. Same-family AI
reviews do not make these questions independent gold. No findings or metrics are
produced by this review. Do not reclassify missing detections as unsupported.
Product implementation and source-only/non-decrypting behavior have not changed.
The new shorter user text is not permission to expand the documented subset.

Freeze the assessment only after both independent reviews exist and bind their
exact bytes. Keep all previous applicability records intact. Admission requires
matching dispositions/current hashes and no unresolved questions, followed by
current offline admission and guarded quality checks. Hosted CI and exact-source
package/provenance verification remain separate stages.
