# Source-first external parameter-reference annotation

The scope is twelve frozen line intervals in two pinned public OSS files. No
third-party source is copied. Units use one-based lines and half-open Unicode
code-point columns. This scope is not a repository, language, API or cryptography
accuracy estimate. Source and source-span hashes are fixed in corpus.json.

A positive unit contains a concrete, standardized ML-KEM or ML-DSA parameter-set
name as a nominal executable-source symbol or literal. Declarations, imports and
unused code count as references, without implying runtime use or conformance.
Comment-only documentation and code examples in comments are negative for this
AST-source reference scope. Generic unknown names are ambiguous, and unsupported
input is unsupported. A negative is never inferred from a missing finding.

Use the actual source, surrounding module declarations and NIST FIPS203/FIPS204
primary definitions. Do not read scanner output, rule regexes, another label file
or previous tuning observations. Do not run or import upstream source. Record the
source/document evidence, role, parameter, label, exposure and uncertainty for
each interval. Each fresh annotator writes only their own assigned label file.
Distinct agent names or same-model agreement alone do not establish independence.
The coordinator must adjudicate source facts before viewing target predictions.
Retain unresolved independence or completeness as unevaluated, with null metrics.

Use existing evaluate.load_truth and external.score_annotated if qualified truth
is admitted. Preserve out-of-interval predictions and other-rule counts. Positive
and negative sampling is deliberate, not a prevalence sample. Do not tune on this
scope and still describe it as unused validation.
