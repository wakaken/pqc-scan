# pqc-scan

[English](README.md)

`pqc-scan` は、耐量子暗号（PQC）への移行調査に使うRust製のコマンドラインツールです。
ローカルのプロジェクトを読み、暗号方式やライブラリへの参照、その位置、確認すべき点をレポートにまとめます。
JWT、TLS、PKI、SSHなどの暗号処理を変更する前に、調査する箇所を絞り込むために使います。

スキャンからレポート生成まで、ローカルのルールと構文解析で完結します。LLMやAIサービスへの接続は不要で、これらの処理中に外部通信や、ソースコード・検出結果の外部送信を行いません。AIサービスのAPIキーや契約も必要ありません。

ビルド・インストール時の依存パッケージ取得、利用者が設定するCIでのレポート送信、外部の参考リンクの閲覧は別の通信です。ツールとルールが手元に揃えば、オフラインでスキャンできます。

## スキャンできる成果物

ローカルのリポジトリを指定して、次の成果物を検査します。形式ごとに対応するパターンや解析範囲があります。

| 成果物 | 対象言語・ファイルの例 | 確認する内容 |
|---|---|---|
| ソースコード | Java、Go、JavaScript、TypeScript／TSX、Python、Rust、Ruby | 暗号API、方式名、関連する利用パターン。TypeScript・TSXはそれぞれ専用の文法で解析します |
| 設定ファイル | Kubernetes／Ingress、nginx、Apache httpd、Envoy、Istio、HAProxy、Traefik | TLS、暗号スイート、鍵交換グループなどの設定 |
| 公開証明書 | `.pem`、`.crt`、`.cer`、`.der` | 署名方式と公開鍵の方式、対応する鍵長・曲線、有効期間、公開情報の指紋 |
| 秘密鍵のマーカー | RSA、汎用PKCS#8、OpenSSHの秘密鍵ヘッダー | 対応するヘッダーの存在。復号や秘密鍵の妥当性確認は行いません |
| 依存関係の定義・ロックファイル | `Cargo.toml`、`Cargo.lock`、`package.json`、npm／pnpmのロック、Python・Ruby・Java・Goの依存関係ファイル | 関連ライブラリ、指定されたバージョン条件、対応する解決済みレコード |
| 既存のSBOM | CycloneDX JSON、SPDX JSON | 申告された依存コンポーネントやパッケージ。インストール状態の確認ではありません |

PKCS#12（`.p12`／`.pfx`）では、非暗号化の公開証明書を取り出して検査できます。暗号化された内容と秘密鍵のbagは対象外で、パスワード入力・復号・完全性や信頼性の検証は行いません。
詳しいファイル一覧、対応する版、解析の制約は[対応する入力と検査範囲](docs/user/COVERAGE.ja.md)に記載しています。
稼働中の接続先は、別途有効にして明示実行する[TLS・SSH診断](docs/user/PROBING.ja.md)で調べます。
リポジトリのスキャン対象にはなりません。任意のプログラミング言語への対応も保証しません。

<a id="features"></a>

## ツールの主な機能

- 暗号利用の手掛かりを探し、重大度・リスク・ソースの位置を示します。
- 言語や実行環境に応じた移行の確認事項を提示します。
- 調査用のHTML・Markdownと、自動処理用のJSON・SARIFを出力します。
- 暗号利用の所見とソフトウェアの依存関係を、別々の一覧にまとめます。
- 必要に応じて、詳しい観測記録、ローカル方針による評価、検査状況の診断を追加できます。

PQC方式の名前が見つかっても、アプリケーションで正しく使われているとは限りません。
このような所見の意味は、[結果の読み方](docs/user/REPORTS.ja.md#pqc-findings)で例を使って説明しています。

<a id="quick-start"></a>

## 使い始める

[`rust-toolchain.toml`](rust-toolchain.toml)で指定したRust（現在は1.93.1）を使い、このリポジトリのソースからインストールします。

```bash
cd /path/to/pqc-scan
cargo install --locked --path crates/pqc_scan_cli
```

インストール後も、このリポジトリの `rules` ディレクトリを参照できる場所に残してください。
バイナリにルールディレクトリは含まれないため、別のプロジェクトを調べるときは `--rules-dir` を絶対パスで指定します。
コマンドが見つからない場合は、`~/.cargo/bin` が `PATH` に含まれているか確認してください。

```bash
pqc-scan scan /path/to/your-product --format all --out-dir /path/to/reports/product-scan --rules-dir /path/to/pqc-scan/rules
```

実行結果を比較するときは、検査対象のリポジトリの外に新しい出力先を用意します。
過去のレポートを入力として読み込んだり、今回の出力と取り違えたりするのを避けるためです。
HTML・Markdownを日本語にするには `--lang ja` を加えます。[インストールせずにソースから実行する方法](docs/user/SCANNING.ja.md#from-source)もあります。

<a id="results"></a>

## 結果を確認する

HTMLは検査範囲と未完了の確認から読み始められます。観測・資産ごとの詳しい記録はJSON・Markdownに残します。

まず `report.html` を開きます。所見ごとのファイル位置、周辺のコード、確認事項を読み、実際に修正が必要か判断してください。
同じ種類の所見が多い場合は検索・絞り込みを使えます。テキストで共有・保管する場合は `report.md` を使います。
どちらにも検査状態を表示し、ローカル評価を選ぶと参考となる判定も確認できます。

`--format all` では、`report.html`、`report.md`、`report.json`、`report.sarif`、`cbom.json`、`dependency-sbom.json` の6ファイルを出力します。
最後の2つは、それぞれ暗号利用の所見とソフトウェアの依存関係の一覧です。
用途や関係は[用途に合うレポートを選ぶ](docs/user/REPORTS.ja.md#choose-report)で説明しています。
詳しい棚卸し、評価、診断情報を加えるには、それぞれのオプションが必要です。
CycloneDX 1.7形式には `--cyclonedx-17`、同じリポジトリ範囲の棚卸し比較には `diff` を使います。
指定方法と制約は[結果の読み方](docs/user/REPORTS.ja.md)を参照してください。

## 制約と秘密情報の扱い

静的な調査のため、誤検出や見逃しがあります。所見は実際に稼働している証拠ではなく、検出がゼロでも検査の完了や安全性は保証しません。
リポジトリのスキャンでは、接続先との通信、証明書の信頼チェーンの検証、依存関係のインストール、PQC移行完了の認定は行いません。
任意の `probe` コマンドは、明示した接続先へ通信します。TLSは通常の証明書・名前検証、SSHは未認証の提示方式の収集を行います。

対応する秘密鍵・認証情報の構文をマスクし、プレビューも保守的に扱います。
あらゆる秘密情報を見つける機能ではなく、未知・難読化された内容や、パス・識別子に含まれる秘密は対象外になる場合があります。
レポートを共有する前に[秘密情報の扱いと除外範囲](docs/user/COVERAGE.ja.md#privacy)を確認してください。
