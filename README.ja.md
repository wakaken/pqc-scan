# pqc-scan

[English](README.md)

`pqc-scan` は、耐量子暗号（PQC）への移行調査に使うRust製のコマンドラインツールです。
ローカルのプロジェクトを読み、暗号方式やライブラリへの参照、その位置、確認すべき点をレポートにまとめます。
JWT、TLS、PKI、SSHなどの暗号処理を変更する前に、調査する箇所を絞り込むために使います。

ローカルファーストであり、スキャンからレポート生成までローカル環境で完結します。これらの処理中に、インターネット経由で外部サービスへ接続することはありません。外部のAIサービスやLLMへ自動的に接続することもなく、スキャン対象のソースコードを外部へ送信しません。

## スキャンできる成果物

ローカルのリポジトリを指定して、次の成果物を検査します。形式ごとに対応するパターンや解析範囲があります。

| 成果物 | 対象言語・ファイルの例 | 確認する内容 |
|---|---|---|
| ソースコード | Java、Go、JavaScript、TypeScript／TSX、Python、Rust、Ruby | 暗号API、方式名、関連する利用パターン |
| 設定ファイル | Kubernetes／Ingress、nginx、Apache httpd、Envoy、Istio、HAProxy、Traefik | TLS、暗号スイート、鍵交換グループなどの設定 |
| 公開証明書 | `.pem`、`.crt`、`.cer`、`.der` | 署名方式と公開鍵の方式、対応する鍵長・曲線、有効期間、公開情報の指紋 |
| 秘密鍵のマーカー | RSA、汎用PKCS#8、OpenSSHの秘密鍵ヘッダー | 対応するヘッダーの存在。復号や秘密鍵の妥当性確認は行いません |
| 依存関係の定義・ロックファイル | `Cargo.toml`、`Cargo.lock`、`package.json`、npm／pnpmのロック、Python・Ruby・Java・Goの依存関係ファイル | 関連ライブラリ、指定されたバージョン条件、対応する解決済みレコード |
| 既存のSBOM | CycloneDX JSON、SPDX JSON | 申告された依存コンポーネントやパッケージ。インストール状態の確認ではありません |

ファイルのサイズ上限は既定で2MiBです。`scan --max-file-size-mib 16` またはフォルダ選択画面のサイズ欄で1〜64MiBに変更できます。詳しくは[ファイルサイズの上限](docs/user/SCANNING.ja.md#ファイルサイズの上限)を参照してください。

<a id="features"></a>

## ツールの主な機能

- 暗号利用の手掛かりを探し、重大度・リスク・ソースの位置を示します。
- 言語や実行環境に応じた移行の確認事項を提示します。
- 調査用のHTML・Markdownと、自動処理用のJSON・SARIFを出力します。
- 暗号利用の所見とソフトウェアの依存関係を、別々の一覧にまとめます。
- 必要に応じて、詳しい観測記録、ローカル方針による評価、検査状況の診断を追加できます。
- 明示的に呼び出す`assess`コマンドで[保存済みの証拠をオフラインで再評価](docs/user/SAVED-EVIDENCE.ja.md)し、技術的役割、適用範囲を定めた申告、移行判断を分けて扱えます。
- 検出結果に用途・利用状況を入力し、移行に必要な確認事項を整理できます。

PQC方式の名前が見つかっても、アプリケーションで正しく使われているとは限りません。
このような所見の意味は、[結果の読み方](docs/user/REPORTS.ja.md#pqc-findings)で例を使って説明しています。

## 使い始める

[`rust-toolchain.toml`](rust-toolchain.toml)で指定したRust（現在は1.93.1）を使い、このリポジトリのソースからインストールします。

```bash
cd /path/to/pqc-scan
cargo install --locked --path crates/pqc_scan_cli
```

アーカイブの検証と導入方法は[インストールガイド](docs/user/DISTRIBUTION.ja.md)を参照してください。macOS Apple Silicon向け静的版の公開物は[GitHub Releases](https://github.com/wakaken/pqc-scan/releases)で確認してください。probe同梱版は公開前の確認が残っています。

インストール後も、このリポジトリの `rules` ディレクトリを参照できる場所に残してください。
バイナリにルールディレクトリは含まれないため、別のプロジェクトを調べるときは `--rules-dir` を絶対パスで指定します。
コマンドが見つからない場合は、`~/.cargo/bin` が `PATH` に含まれているか確認してください。
`pqc-scan --help`・`pqc-scan --version` で導入したコマンドを確認できます。どちらもスキャンや通信を行わず、正常終了します。

```bash
pqc-scan scan /path/to/your-product --format all --out-dir /path/to/reports/product-scan --rules-dir /path/to/pqc-scan/rules
```

実行結果を比較するときは、検査対象のリポジトリの外に新しい出力先を用意します。
過去のレポートを入力として読み込んだり、今回の出力と取り違えたりするのを避けるためです。
出力先の経路やファイル位置にあるシンボリックリンクは拒否します。通常の既存レポートは上書きできます。詳しくは[出力先の安全性](docs/user/SCANNING.ja.md#出力先の安全性)を参照してください。
HTML・Markdownを日本語にするには `--lang ja` を加えます。[インストールせずにソースから実行する方法](docs/user/SCANNING.ja.md#from-source)もあります。

## ブラウザでスキャンする

上の手順でCLIをインストールしたら、簡易Webサーバーを起動します。

```bash
pqc-scan serve --root /path/to/projects --rules-dir /path/to/pqc-scan/rules
```

1. 既定のブラウザでトップ画面が開きます。開かない場合は、ターミナルに表示された `http://127.0.0.1:8787/<session>/` の完全なURLを開きます。
2. `--root` 内の一覧やチェックボックスで対象フォルダを複数選び、**選択したフォルダをスキャン**を押します。ダブルクリックで開き、「戻る」「進む」や一覧上のパスで階層を移動できます。指定したルートの外へは移動できず、シンボリックリンクも表示しません。
3. 進捗モーダルで他の画面操作を止め、選択した順にスキャンします。結果はフォルダごとに残ります。複数の場合は結果一覧の各フォルダから、そのフォルダのスキャンレポートを開くか、利用できる場合は移行の確認へ進めます。スキャン履歴のカードにも同じ操作があります。通常モードで1フォルダだけの場合は、HTMLレポートが自動で開きます。検出結果とともに、検査が完了した範囲を確認してください。ブラウザで戻ると、別のフォルダもスキャンできます。
4. 終了時は **Ctrl+C** でサーバーを停止します。レポートはターミナルに表示された非公開の `pqc-scan-web-*` ディレクトリに残ります。オフラインで読む場合は `report.html` と `report.rules.html` を一緒に保管してください。

サーバーは `127.0.0.1` だけで待ち受け、CLIと同じ静的スキャンを実行します。ソースやレポートの外部送信は行いません。ポートが使用中なら `--port 0`、ブラウザを自動で開かない場合は `--no-open` を指定します。配布物を展開して使う場合は、コマンドを `/path/to/bundle/bin/pqc-scan`、ルールを `/path/to/bundle/rules/default` に置き換えます。詳しい制約とオプションは[ローカルWebスキャン](docs/user/SCANNING.ja.md#ローカルwebスキャン)を参照してください。

<a id="migration-review"></a>

## 移行確認を使う

`serve` に `--migration` を加えると、スキャン結果から用途・利用状況を入力し、
「確認事項を作成」で移行確認へ進めます。複数フォルダや履歴では、対象名の付いたカードから
「スキャンレポートを開く ↗」で検出結果、「移行の確認へ進む」でその対象の入力・結果を開きます。
移行確認は判断ごとに「やること」と「次に進める条件」を示します。評価日時、日程、早急な
調査から確認し、検出箇所で根拠を調べてください。

[画面付きの8ステップ](docs/user/SCANNING.ja.md#web-migration-walkthrough)に沿って操作できます。詳しくは[入力と再評価](docs/user/SCANNING.ja.md#移行情報の任意入力と再評価)、
[移行確認の読み方](docs/user/REPORTS.ja.md#saved-assessment)、
[保存済み入力と申告](docs/user/SAVED-EVIDENCE.ja.md)を参照してください。入力JSONは対応する
棚卸しと一緒に保存します。「評価データを保存」は評価結果の保存であり、再利用する入力
contextの保存とは別です。

## 結果を確認する

HTMLでは検出件数、検査範囲、未完了の確認をまとめて表示します。観測・資産ごとの詳しい記録はJSON・Markdownに残します。
評価方針による参考判定はHTMLに表示せず、明示的に求めたJSON・Markdownに残します。

まず `report.html` を開きます。所見ごとのファイル位置、周辺のコード、確認事項を読み、実際に修正が必要か判断してください。
同じ種類の所見が多い場合は検索・絞り込みを使えます。テキストで共有・保管する場合は `report.md` を使います。
Markdownでは、CR・LFを含む複数行のソース断片やコード例もコード表示の中に収めます。
どちらにも検査状態を表示します。ローカル評価の参考判定はMarkdownと明示的に指定したJSONに出力し、HTMLには表示しません。

フォルダ選択からレポート生成まで画面上で操作するには、[ブラウザでスキャンする](#web-scan)を参照してください。

`--format all` では、`report.html`、`report.md`、`report.json`、`report.sarif`、`cbom.json`、`dependency-sbom.json` の従来の6ファイルに、ルール解説の `report.rules.html` を加えて出力します。
`cbom.json` と `dependency-sbom.json` は、それぞれ暗号利用の所見とソフトウェアの依存関係の一覧です。
用途や関係は[用途に合うレポートを選ぶ](docs/user/REPORTS.ja.md#choose-report)で説明しています。
詳しい棚卸し、評価、診断情報を加えるには、それぞれのオプションが必要です。
CycloneDX 1.7形式には `--cyclonedx-17`、同じリポジトリ範囲の棚卸し比較には `diff` を使います。
指定方法と制約は[結果の読み方](docs/user/REPORTS.ja.md)を参照してください。

HTML・Markdownは同じ位置・方式・指摘内容を1件にまとめ、一致したルールを詳細に残します。検査対象はファイル数、指摘は統合後の件数です。JSONなどの機械向け出力は元のルール別記録を保持します。

テストは既定で含みます。CLIの `--exclude-tests` またはブラウザの「選択をすべて解除」の下にある「テストコードを除外」で、一般的なテスト用パス・ファイル名を任意に除外できます。条件と限界は[スキャン方法](docs/user/SCANNING.ja.md)を参照してください。 `.pqcignore` で独自の除外パスも指定でき、Rustでテスト専用と確認できた部分の検出も除外します。

## 制約と秘密情報の扱い

静的な調査のため、誤検出や見逃しがあります。所見は実際に稼働している証拠ではなく、検出がゼロでも検査の完了や安全性は保証しません。
リポジトリのスキャンでは、接続先との通信、証明書の信頼チェーンの検証、依存関係のインストール、PQC移行完了の認定は行いません。
実験的な `probe ssh-kex`（`probe-ssh-kex` 機能）は、指定した信頼済みEd25519ホスト公開鍵と照合し、ML-KEM768＋X25519のハイブリッド鍵交換を確認します。ユーザー認証・ログインは行いません。独立した `probe.ssh-kex.v1.json` と日本語・英語のHTML／Markdownを出力し、従来の出力形式は維持します。詳細は[診断ガイド](docs/user/PROBING.ja.md)を参照してください。

任意の `probe` コマンドは、明示した接続先へ通信します。TLSは通常の証明書・名前検証、`probe ssh` は未認証の提示方式の収集を行います。

対応する秘密鍵・認証情報の構文をマスクし、プレビューも保守的に扱います。
あらゆる秘密情報を見つける機能ではなく、未知・難読化された内容や、パス・識別子に含まれる秘密は対象外になる場合があります。
レポートを共有する前に[秘密情報の扱いと除外範囲](docs/user/COVERAGE.ja.md#privacy)を確認してください。

読み取るのは、指定したサイズ上限内の通常ファイルです。Gitのignore設定、除外ディレクトリ、既知のバイナリ形式は検査範囲に含めません。解析を完了できなくても、読み取れた部分の所見は残します。
理由を確認するには `--diagnostics`、未完了の検査でCIを失敗させるには `--require-complete` を使ってください。[検査状態の読み方](docs/user/SCANNING.ja.md#diagnostics)と[対応範囲・上限](docs/user/COVERAGE.ja.md)に詳しい説明があります。
