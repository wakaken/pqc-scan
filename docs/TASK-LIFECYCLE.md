# Task Lifecycle
This document defines the lifecycle of tasks used by AI agents in this repository.
Tasks are stored as YAML files in the `tasks/` directory.
Agents collaborate through the task queue by updating task statuses according to the rules defined below.

---

# Status Progression

- Tasks move through the following lifecycle:
  pending → planned → in-progress → review → done

- An optional state may also be used when progress cannot continue:
  - blocked

---

# Status Definitions

## pending

The task exists in the queue but has not yet been selected for execution.

Typical sources:

- newly created tasks
- tasks generated by reflection
- tasks generated by monitoring or analysis

Ownership: Planner, Reflection, Monitor  

These agents are allowed to create tasks with the `pending` status.

---

## planned

The task has been selected for execution and an implementation plan exists.

Ownership: Planner  

Only the Planner agent may change a task from `pending` to `planned`.

---

## in-progress

Implementation work has started.

Ownership: Executor  

The Executor agent sets this status when development begins.

---

## review

Implementation is complete and the task is ready for review.

Ownership: Executor  

The Executor agent sets this status when implementation is complete and the task is ready for Reviewer assessment.

---

## done

The task is complete and validated.

Ownership: Evaluator  

The Evaluator agent confirms the results of reviews.

## blocked (optional)

This status indicates the task cannot proceed without human input.

Typical reasons:
- unclear specification
- architectural decisions required
- unexpected events

Ownership: Any agent may set a task to blocked.  

Human review is required before work continues.
