# Selected cryptographic OSS evaluation

The active evaluation contains 27 main projects and eight comparison projects
selected from the existing registry of 98. The other 63 main projects remain
future work. Their acquisition, source and historical evidence remain preserved.
The original 98-project protocol and results remain historical records.

The main selection contains three projects in each of nine language groups.
JavaScript and TypeScript form one group, as do C and C++. The explicit selection
replaces Teleport with age, Forge with noble-post-quantum, and aws-lc-rs with
RustCrypto/KEMs. The original priority flag does not identify this selection.
Use the exact repository IDs in the run's immutable `SELECTION.json`.

The selection is purposive and emphasizes cryptographic implementations and API
use across classical cryptography, TLS, SSH, PKI, JWT and PQC. It is neither a
random sample nor an unused holdout. Preserve each selected repository's fixed
commit, input scope, file hashes, exposure and tuning history. Retain the
user-approved unavailable-file exclusions for Node.js and Discourse.

Run the existing static scanner with one thread, one attempt, a 600-second
timeout, a 2 MiB file limit, all required report formats and the recorded free
disk admission limit. Set `collectPerformance` to false. Do not execute scanned
code, resolve its dependencies, or collect CPU, RSS, load or swap observations.
Record terminal failures and continue to later repositories when integrity holds.

Bind the scanner binary to the existing frozen product source, successful default
build commands, target inventory and rules. Bind the current evaluation tools
separately. The new current-clock descriptive run does not inherit the old
98-project execution or historical clock-replay permissions. Time-dependent
before-and-after conclusions remain unknown without matching time conditions.

Keep main and comparison aggregates separate. Filter existing immutable source
truth and adjudication by the exact selected IDs. This yields 140 sampled owned
lines and two canonical scoring units, one each in RustCrypto/KEMs and ruby-jwt.
Authenticate the original truth, source files, mapping and scorer before reuse.
Reuse the existing scorer for these intervals. Do not carry the original 392-line
or 324-claim denominators into this evaluation.

The original same-family AI raters and adjudicator retain their identities and
output-exposure records. Their separation does not establish independent truth.
Report precision, recall and F1 only where the truth and applicable scoring
conditions support them. Preserve unknown, unsupported, partial and failed states.
Do not infer accuracy from finding counts or convert an unjoined Native property
to a false negative automatically.

Complete a small actual-input scan, output audit and bounded score before
expanding to representative projects and all selected 35. Reassess confirmed
fixes, retain unresolved improvement themes, inspect representative actual HTML
in a browser, and obtain independent technical and work-record reviews. Required
validation remains required. This evaluation does not authorize publication,
develop integration, a release, performance measurement or external contact.
