This protocol extends the historical study without replacing its protocol,
measurements, observations, or task076–087 evidence. The registry is
`benchmark/registry.json`. The original request specifies 90 primary repositories,
nine groups, eleven individual languages, and eight separate comparison targets.
A checked-out source snapshot is never an executable dependency of this study.

## Freeze label scope and exposure

The 48 historically exposed primary projects are the tuning population.
The remaining 42 primary projects initially formed reserved holdout candidates. Before the first formal population run, noble-post-quantum source facts were used for the finite underscore-name repair. That entire lineage is now calibration. The frozen formal-run split is49 tuning projects and41 unused validation candidates. The initial48/42 allocation remains recorded in the decision trail and source-fact freeze; no result from the consumed lineage is reported as unused validation. Before any
holdout scanner output is viewed, freeze its selected source intervals, expected
facts, completeness, references, labeler exposure, and adjudication record.
A holdout labeler must not consume tuning-dependent output or predictions for the
labeled interval. If this cannot be established, downgrade the independence
status and leave its population accuracy unevaluated. Separate model sessions
and code review do not by themselves establish independent truth.

The intended scoring unit is one source-bound operation or explicit reference
within a fully annotated file/rule/line interval. Each label records repository
SHA, actual file SHA-256, exact interval, context, algorithm family, parameter,
use or unknown-use state, applicable rule, positive or negative judgment,
source/primary-document references, author exposure, and adjudication status.
Implementation, call, configuration, dependency, and test/example references
remain distinct. X.509 and SSH protocols are distinct from their primitive
algorithms. Draft, standardized, and hybrid PQC references retain that distinction.
Static presence never establishes negotiated use or quantum resistance.

Existing 64 observations and exposed task084/085 labels are research evidence,
not newly independent truth. New exposed observations may support regression
cases, but cannot silently become holdout accuracy labels.

## Reuse scoring and evidence machinery

Use `tests/quality/external.py` for annotated-interval selection and the unchanged
`tests/quality/evaluate.py` scorer. Do not duplicate truth or the matcher under
`benchmark/`. A new observation ledger links existing records by path and ID.
Compute TP, FP, FN, Precision, Recall, and F1 only for independently justified,
complete, applicable intervals. Otherwise emit null and an explicit reason.
Unattributed findings remain separate. Never generalize a partial score to an
entire project, language, or the 90-project population.

## Run and compare

Start with a small pinned input. Validate real outputs and diagnostics before
expanding to the priority27 and then primary90. Preserve the separate comparison8.
Use one scanner thread, default 2 MiB per-file cap, explicit frozen rules,
all static report formats, diagnostics, inventory JSON, and optional CycloneDX
1.7 exports. Record exact flags. Store large outputs and foreign sources outside
Git. New attempts never overwrite old logs, manifests, or receipts.

Bind source, binary, rules, harness, protocol, registry selection, actual input
population, external ignore settings, environment, and output artifacts.
Verify input and selection before and after the scan. Resume only when every
required binding and complete artifact still matches. A successful process may
still have partial inspection. Failed, timed-out, interrupted, unsupported,
unknown, and partially inspected attempts remain distinct.

Use existing measurement helpers for elapsed time, child CPU and child peak RSS.
Record native units and scope. Peak RSS is not aggregate process-tree memory.
Record explicit limits and which are enforced versus observed. Check free space
before expansion. Do not start acquisition or builds that can exhaust evidence
storage. Never delete historical inputs or measurements to make a run fit.

Performance comparisons require at least five alternating samples per side on
the same exact input root and configuration. Exclude builds and acquisitions,
serialize scans, check host load, and preserve all samples. Report median and
range. Identify a measured limiter before claiming a speedup; missing controls
make the comparison inconclusive. Full-population first-pass timings remain
single-sample descriptive measurements, not a stable performance ranking.

Compare machine output content, totals, ordering and references using existing
semantic/order digests and format contracts. Intentional format omissions are
not inconsistencies. Verify representative HTML in a real browser over a
dedicated loopback server, including English/Japanese, search, filters, sorting,
keyboard/layout, boundary data, accessibility, offline behavior and XSS controls.
Follow docs/agent/REPORTS.md. Bind captures to the exact generated artifacts.
