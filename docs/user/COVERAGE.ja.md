## 証明書と秘密鍵マーカー

次の拡張子を証明書・鍵の検査候補として扱います。

- 証明書候補: `.pem`, `.crt`, `.cer`, `.der`。内容からPEM／DERを判別します。
- `.p12`／`.pfx`では、対応するPKCS#12コンテナー内の非暗号化の公開証明書も検査します。
- 秘密鍵のマーカー:
  - `BEGIN RSA PRIVATE KEY`
  - `BEGIN PRIVATE KEY`
  - `BEGIN OPENSSH PRIVATE KEY`

証明書の署名方式と、証明書に含まれる公開鍵の方式を分けて解析します。
RSA鍵長はmodulusの実ビット長、ECは対応する名前付き曲線（P-256／P-384／P-521）の
フィールドサイズです。公開鍵のエンコード長を鍵長として扱いません。
Ed25519／Ed448／X25519／X448はエンコード長を別に記録し、RSA鍵長や安全性強度を推測しません。
未知・PQCの公開鍵形式はOIDと公開オブジェクトのフィンガープリントを保持し、意味上の鍵長は不明とします。
PQCのOIDがあるだけでは、有効なPQC鍵とは判断できません。

既存の証明書所見のmetadataに、証明書・SPKIのSHA-256、各エンコードのバイト長、
鍵の方式・パラメーター、判明した鍵長・曲線、有効期間のタイムスタンプ、オブジェクト位置を記録します。
PEMバンドルでは実際の行・列とブロック番号を保持し、同じ公開鍵を持つ別の証明書も残します。
DERの行・列は互換性のため従来の1:1を維持し、`byte_offset: "0"`を記録します。
これはソースコード上の位置を意味しません。不正・未対応ブロックが混在しても解析できた証明書を残し、
`--diagnostics`で検査が不完全だったことを報告します。
署名・信頼チェーン・鍵や曲線上の点の数学的な正当性は検証しません。
PKCS#12の復号と、単独の公開鍵ファイルの検出は対象外です。

組み込みの証明書署名ルールは、解析したOIDと完全一致で照合します。RSA鍵長のルールは
RSA／PSSの公開鍵modulusを対象とし、ファイル名やECのエンコード長では成立しません。
ECDSA・DSAは `quantum-vulnerable` として扱います。既存のPKI昇格処理を適用すると、
最終的な重大度はそれぞれhigh・criticalです。SHA-1・MD5・弱いRSA鍵の問題は別の所見で示します。
DSAは、署名の置き換えと過去の署名の検証を分けて移行を検討します。

`CERT_EXPIRED` と `CERT_NOT_YET_VALID` は、解析したUTC時刻と明示的な判定時刻を使います。
有効期間の両端は含みます。既存ID `CERT_EXPIRY_2026_OR_BEFORE` は、2027年1月1日UTCより前に
期限を迎えるかという固定基準を維持し、従来の基準であることを明記します。現在の期限切れとは別の判定です。
期間の前後が逆、または判定時刻が取得できない場合は、静的な検出を残して不完全な検査として報告します。
時刻判定の所見には、既存のmetadataへ `assessment_time_unix` と `validity_status` を記録します。

CLIはスキャンごとに証明書の判定時刻を取得します。

カスタムルールの `certificate` など、従来のscopeは複合文字列の照合を維持します。
新たな予約名 `rsa_modulus_bits`・`certificate_validity`・`legacy_not_after_2026` は例外です。
外部ルールがこれらを独自ラベルとして使っていた場合は、更新前に別名や `certificate` へ変更してください。
`signature_oid`・`public_key_oid` は引き続き識別子のみを対象とします。
証拠の分離や分類修正により、対象の証明書の検出結果・ID・従来CBOMの方式文字列は意図的に変わります。
CLIオプション、出力構造・列挙値、ID生成・重大度を引き上げるの処理は維持します。
署名・信頼チェーン・実際の利用状況は保証しません。PSSのダイジェストパラメーターや未収載OIDの評価には
制限があり、ハッシュの所見がないだけで安全とは判断できません。
[分類仕様](../roadmap/TASK-021-IMPLEMENTATION.md)と[証明書限定の比較結果](../quality/CERTIFICATE-BASELINE-021.md)を参照してください。
EC・DSA・暗号化秘密鍵のPEMマーカーを含むファイルも、ソース抜粋全体をマスクします。
新たな秘密鍵検出ルールの追加や、鍵の復号は行いません。

### PKCS#12の対応範囲

PFX v3のData・AuthenticatedSafe・SafeContentsとX.509証明書bagを、長さが確定したDER形式の範囲で読みます。
取り出した公開証明書はPEM・DERと同じ属性解析に渡します。入れ子は有限の深さまで扱い、長さ不定のBER形式や分割されたOCTET STRINGは対象外です。

暗号化された内容、秘密鍵のbag、未知のbagや内容形式は展開しません。公開証明書と混在している場合は、読めた証明書を残して部分成功とします。
暗号化のみの場合は未対応、不正な構造は部分成功、上限到達は打ち切りとして報告します。コンテナーの所見には固定の理由と、MAC・信頼性の検証を行っていないことを記録します。
構造の検査完了は、完全性や信頼性の保証ではありません。

上限は2 MiB、bag数256、内容エントリー256、入れ子の深さ8、属性値4096件です。
不正な内容がテキストに見えても、P12・PFXからソースプレビューや抜粋を出力しません。従来のバイナリ位置は1:1と実際のバイト位置を維持し、棚卸しでは位置不明とオブジェクト番号を使います。

### 組み込みルールセット

- デフォルトルールは `rules/default/` 配下にあります。
- 現在の組み込みルール数: 119件
- ルールIDと重大度の定義は[ルール一覧](../rules-reference.md)を参照してください。

空白だけのID、有限でない信頼度や `0〜1` の範囲外の値、IDの重複、不正なパターン、ルール探索の失敗は実行エラー1になります。
一部のルールだけを読み込んで成功したとは扱いません。有効な独自scopeは検出器ごとの動作を維持し、未知のscope名だけを理由に拒否しません。
独自ルール集を更新するときは[scopeの互換仕様](../architecture/RULE-VALIDATION.md)も確認してください。

## ソースコードの解析範囲

同じ行に同じ呼び出しが複数あっても、ソース上の位置が異なれば別々の所見として保持します。
親子のASTノードが同じ一致箇所を表している場合は1件にまとめます。
ルール・ファイル単位の採用上限は4,096件とし、実際の作業上限に達した場合は診断を残します。
表示用に付けた省略記号をソースの一致として扱いません。
CLI・出力形式・ファイル名・既存の出現箇所のIDは維持しますが、保持される所見数と
新しい出現箇所のIDは意図した修正として増える場合があります。AST列のUnicodeに関する
既知の制約は引き続き適用されます（[SARIFの位置情報](REPORTS.ja.md#sarif-locations)を参照してください）。

TypeScriptとTSXは、それぞれ専用の文法で解析します。JavaScriptとは異なる正しい型構文だけを理由に部分解析とはしません。
構文エラーがあれば、取得できた所見を保持して部分成功を報告します。別名importの見逃し、同名関数や表示文字列の誤検出、祖先ノード内のコメントの扱いには引き続き制約があります。
名前解決やデータフロー解析を行うものではありません。

## 秘密情報の扱いと除外範囲

認識できる秘密鍵ブロックや認証情報は、出力する検出根拠でマスクします。
RSA、汎用PKCS#8、OpenSSH、EC、DSA、暗号化秘密鍵のマーカー、単一行の名前付きパスワード・トークン・鍵の値、
Bearer／Basicトークン、HTTP(S) URLの認証部分と名前付き認証クエリーが対象です。秘密鍵の解析や復号に対応するという意味ではありません。

認証情報や秘密鍵を認識したファイルでは、プレビューを保守的に置き換えます。
メタデータの値、対処案とコード例、CBOM、依存関係の自由文にもマスク処理を適用します。
型を限定した棚卸しや診断情報には、元の本文や任意のエラー本文を含めません。

あらゆる秘密情報を見つける機能ではありません。未知・難読化された構文、任意の認証項目名、複数行の認証情報の位置追跡、構造を表す項目に埋め込まれた秘密は対象外です。
パス、ID、repository scope、独自メタデータのキーには秘密情報を入れないでください。
公開証明書の指紋・subjectなど、残す情報にも共有先に応じた確認が必要です。保守的な処理で公開テキストのプレビューも省略する場合があります。
[対応構文・項目ごとの方針・制約](../architecture/EVIDENCE-PRIVACY.md)と[ダミー値による検証](../quality/TASK-029-EVIDENCE-PRIVACY.md)に詳細を記載しています。

走査ではGitのignore設定を尊重し、既定で `.git`、`node_modules`、`target`、`dist`、`docs` とMarkdownファイルを除外します。
2 MiBを超えるファイルも対象外です。テストディレクトリ全体を除外する動作はありません。
スキャンに成功しても、除外したファイルや未対応形式に暗号利用がないとは判断できません。

## 実リポジトリ向けの上限と文字コード

構文候補は元のソース全体を参照し、以前の2,000文字での検査打ち切りはなくなりました。表示用プレビューだけを短縮します。既定の上限は、構文候補262,144件、処理予定ノード2,000,000件、ルール・ファイルごとの採用ヒット4,096件と一致候補65,536件、ファイル全体でASTルールが調べる候補テキストの累計256MiBです。採用上限ちょうどと追加の有効ヒットを区別し、実際の上限到達は `detector_truncated` として残します。未検出の所見数を示す値ではありません。ライブラリでは `DetectorBudget` と各検出器の `with_budget` で明示的な上限を指定できます。

固定した文法で未対応のTypeScript `export type *`（名前空間の再エクスポートを含む）とJavaScript・TypeScriptの `import defer * as ...` は、構文解析専用の互換ビューで扱います。実際のトップレベルの宣言に限りASCII修飾子を同じバイト数の空白にし、検出・証拠は元のテキストと位置を使います。他の構文エラーは部分解析のまま残ります。モジュールの実行や稼働時の正しさの検証はしません。

UTF-16LE/BE・UTF-32LE/BEのBOMを認識し、厳密に復号します。BOMなしではASCIIのバイト位置に強い規則性があり、妥当な表示可能Unicodeとなる入力に限定します。BOM付きの不正な文字列は、完了や黙った除外にせず未対応として記録します。検出・ソース表示・マスクに同じテキストを使います。バイナリの暗号コンテナはソース検査に渡さず、復号は行いません。

画像・アーカイブ・コンパイル済みデータ（WebAssembly・MO・protobuf系拡張子を含む）と、テキストとして扱えないバイナリは既定で検査前に除外します。証明書・鍵・信頼ストア等の拡張子は対象に残します。`--include-non-scannable` で通常除外する形式も含められますが、Git ignore・ディレクトリ・2MiBの上限は引き続き適用します。選択件数をリポジトリ全体の列挙数とは扱いません。

依存関係の構造化デコードは500,000値・深さ64に制限し、alias・明示tagは対象外のままです。YAMLの通常・引用・ブロック文字列中の記号と構文上の属性を区別し、空のメタデータ値は妥当なnullとして扱います。

pnpmの単一文書とboot/projectの2文書形式に対応し、両方の依存を別々に棚卸しします。レコードの順序番号はファイル内で重複させません。両文書のschema版が一致し、文書数が2以下であることを確認し、500,000値・10,000レコードの上限はファイル全体に適用します。[pnpm公式の読取り指針](https://github.com/pnpm/pnpm/blob/main/pnpm/docs/lockfile.md)を参照してください。

Dockerfileの判定は最終ファイル名（`Dockerfile` または `Dockerfile.*`）と、コメント・BOMを除いた先頭の `FROM` / `ARG` 命令で行います。同名の通常ソースは各言語で解析し、Dockerfileにも字面の検査を続けます。Bundlerのplatform接尾辞は `PLATFORMS` 宣言で裏付けます（Linux GNUの正規化を含む）。報告値は保持し、レジストリ由来の記録だけで基底の版を解決します。Git/path由来の版は未解決のままです。空の型別名パラメータ、型の位置の `import(...)`、引用符で囲まれたJSX属性は解析専用の互換処理で扱います。実行時importと式の演算子は保持し、不正入力の部分解析表示と処理量の上限も維持します。

### 静的な文脈と条件付き宣言

Mavenの親プロパティは、宣言されたgroup/artifact/versionと一致する、検査対象に選ばれた範囲内の通常ファイルからだけ継承します。空のrelativePathを尊重し、リンク・除外ファイル・範囲外を拒否します。親の参照は16段、入力合計8MiBで打ち切ります。競合するプロパティは未解決とし、同じ値の重複宣言は静的な値として扱います。プロファイル由来の候補には `dep_context`、native観測のcapture status、依存資産のuncertaintyで条件付きと記録します。有効な設定や解決済みの成果物は断定しません。Maven実行、BOM取得、推移依存の解決、インストール状態の判定は行いません。

RubyのGemfile/gemspecは、構文木から文字列リテラルの依存宣言と対応するgroup・platform・分岐を読みます。gemspecの受け手はSpecificationブロックに束縛された変数として確認し、再代入・曖昧な受け手、動的な名前・版、評価・読み込みが必要なものは未完了として残します。委譲された依存宣言はgemspec自身のパス・位置に記録し、Gemfileへ複製しません。Git/path由来の版は未解決のままです。未知のDSL呼び出しも未完了とし、任意のRubyは評価しません。

未生成テンプレートの対応する指示には、原文の位置を保つ静的な解析用の表示を用います。requirementsの分岐に書かれた宣言は、それぞれ条件付き候補として残します。テンプレートの生成・分岐選択は実行せず、生成される値は静的部分が解析できても部分解析のままです。文字列・コメント・正規表現中のテンプレートに似た文字だけで、ソースの指示として扱うことはありません。

対応するV8構文の互換処理では、内部呼び出しの式の位置、通常スクリプトのyield識別子、タグ付きテンプレートのエスケープ、実行時エラーを試す旧来の代入先を扱います。呼び出しは実行せず、実行成功も断定しません。明示されたモジュール・厳格モードと不正構文の境界は保ちます。旧DSAのOID 1.3.14.3.2.12は、既知の公開パラメータと公開整数の形式で解析します。パラメータがない入力は部分解析のままで、鍵長やパラメータは推測しません。根拠は[OpenSSLのOID定義](https://github.com/openssl/openssl/blob/master/crypto/objects/objects.txt)、[DSAデコーダー](https://github.com/openssl/openssl/blob/master/crypto/dsa/dsa_ameth.c)、[Maven POMの仕様](https://maven.apache.org/pom.html)、[Djangoテンプレートの仕様](https://docs.djangoproject.com/en/5.2/ref/templates/language/)です。
