# TLS・SSH接続先の明示的な診断

[English](PROBING.md) · [README](https://github.com/wakaken/pqc-scan/blob/develop/README.ja.md)

macOS Apple Silicon向けのv0.4 `network`版で、次の3種類の診断を使えます。\
（`static`版には `probe` を含みません。詳細は[配布物の選び方](DISTRIBUTION.ja.md#release-status)を参照してください）\

| 調べたいこと | コマンド | 確認できる範囲 |
|---|---|---|
| TLSで選ばれる方式と公開証明書 | [`probe tls`](#tls) | 検証に成功したハンドシェイクの結果 |
| SSHで提示される方式 | [`probe ssh`](#sshの提示方式) | 未認証の提示情報。鍵交換は実行しません |
| SSHハイブリッド鍵交換の成立 | [`probe ssh-kex`](#sshハイブリッド鍵交換と接続先の確認) | 信頼できるホスト公開鍵との一致と、固定した方式での初回鍵交換 |

`probe`を利用する場合、管理者から検査の許可を得たホスト・ポートだけを指定してください。\
`probe` は指定先と通信し、接続先に記録される場合があります。\
なお、リポジトリの `scan` とレポート生成はローカルで完結します。\
ソース内のURL、証明書のSAN、検出結果などから外部サービスへ接続することはありません。

## Probeのコマンドを有効にする

`network`版には3種類のコマンドを同梱しています。\
ソースから導入する場合、以下の通り `--features` を使ってTLSとSSH提示方式には次の機能を有効にします。

```bash
cargo install --locked --path crates/pqc_scan_cli --features probe-tls,probe-ssh
```
SSHハイブリッド鍵交換には、[後述の別機能](#sshハイブリッド鍵交換と接続先の確認)を使います。\
全コマンドを有効にする場合は `--features`  に `probe-tls,probe-ssh,probe-ssh-kex` を指定します。\

<a id="tls"></a>

## 1. TLS

以下の通りホスト名とポート番号を指定して実行します。
```bash
pqc-scan probe tls service.example --port 443 --out-dir /path/to/new-tls-report
```

新しいTLS 1.2／1.3ハンドシェイクを1回行います。\
結果では、選ばれたバージョン、暗号スイート、鍵共有グループ、上限内で取得した公開証明書、診断クライアントの設定を確認します。

### 信頼するCAを指定する

既定は固定したMozilla系ルート証明書を使います。\
以下はローカルの公開CAへ置き換える例です。

```bash
pqc-scan probe tls 127.0.0.1 --port 8443 --allow-cidr 127.0.0.1/32 --server-name localhost --ca-file /path/to/public-ca.pem --out-dir /path/to/new-local-tls-report
```

| 項目 | 動作・条件 |
|---|---|
| `--ca-file` | ルート証明書一覧を置き換えます。公開証明書PEMのみ、最大16個・合計256 KiB。秘密鍵・パスワードは入力しません |
| 証明書の検証 | 信頼チェーン・名前・有効期間の通常検証は必須です。OS固有の信頼制約・失効確認は提供しません |
| `--server-name` | 検証する名前を指定します。DNS名はSNIにも使い、IPアドレスの検証ではSNIを送りません。実際の接続先は変えません |
| 証明書の収集 | 最大16個・256 KiBです。他の処理上限に先に達する場合もあります |
| 行わない処理 | アプリケーション要求、クライアント資格情報の利用、セッション再開、0-RTT、鍵ログ。クライアント認証の要求も未対応です |

検証に失敗した接続を「検証済みの交渉結果」として表示しません。\
失敗や上限到達は検査の不完全さであり、サーバーのPQC非対応や危険性を断定するものではありません。\
TLS 1.3のスイート名だけでは、古典方式とハイブリッド鍵交換を区別できません。

<a id="sshの提示方式"></a>

## 2. SSHの提示方式

```bash
pqc-scan probe ssh service.example --port 22 --out-dir /path/to/new-ssh-report
```

識別文字列とKEXINITを交換し、相手が示す10種類の名前リストと拡張マーカーを順序どおり記録します。\
鍵交換を実行する前に切断します。

| 結果に含むもの | 判断できないこと |
|---|---|
| 相手が提示した方式とバナー | 未認証の情報です。選ばれた方式、検証済みホスト鍵、セッション完了、サーバー全体の移行状況は証明しません |
| 診断クライアントの提案 | 列挙した暗号方式を実装しているという意味ではありません |
| バナーのバージョン・未知の識別子 | バージョンは相手の申告です。不明な識別子は不明のまま残します |

service・userauth・channelの要求や `none` 認証は行いません。\
ユーザー名、agent、秘密鍵、SSH設定、システムのSSHコマンドも使いません。

<a id="sshハイブリッド鍵交換と接続先の確認"></a>

## 3. SSHハイブリッド鍵交換と接続先の確認

ソースから導入する場合は、以下の通り `--features probe-ssh-kex` を指定します。\
管理者などから別の信頼できる経路で入手した、OpenSSH形式の **Ed25519ホスト公開鍵**1つを指定してください。\
未検証の接続先から取得した鍵を、そのまま信頼して利用しないでください。

```sh
cargo install --locked --path crates/pqc_scan_cli --features probe-ssh-kex
pqc-scan probe ssh-kex service.example --port 22 --host-key-file /path/to/trusted-host.pub --lang ja --out-dir /path/to/new-ssh-kex-report
```

| 確認すること | 条件 |
|---|---|
| ホスト公開鍵 | 指定した接続先との照合に使います。4096バイトまでで、名前解決・接続前に検証します。Unixではシンボリックリンク・通常ファイル以外も拒否します |
| 鍵交換方式 | `mlkem768x25519-sha256`（ML-KEM768＋X25519）に固定し、古典方式だけの鍵交換へ切り替えません |
| ホスト署名 | `ssh-ed25519`に固定します。署名を検証し、指定した公開鍵との一致と初回鍵交換の成立を確認して切断します |
| 使用しない入力・処理 | 秘密鍵、ホスト証明書、known_hosts、普段のSSH設定・agent。認証サービス要求、ユーザー名、パスワード、`none` 認証、ログイン、チャネル、リモートコマンドも送りません |

不一致・未知の鍵は拒否し、失敗・未完了では検証済みの方式を記録しません。\
失敗や方式の不一致だけで、サーバー全体がPQC非対応だとは断定しません。\
ホスト認証は古典方式のEd25519なので、ホスト署名のPQC対応や移行完了は意味しません。\
1試行、接続先の固定、アドレス許可、時間・通信量・取消の制限は、次の共通条件に従います。

## 接続許可・上限・出力

### 接続できるアドレス

| 接続先 | 条件 |
|---|---|
| 公開unicast | 既定で許可します |
| 内部・ループバック・特殊用途のunicast | `--allow-cidr` が必要です |
| 未指定アドレス・multicast・限定broadcast | 許可できません |

mapped IPv6を含む全DNS応答を検査し、拒否対象が混在すれば接続しません。\
検証したソケットアドレスを固定し、実際のpeerも照合します。\
proxy、redirect、設定ファイルによる展開、アドレスの再試行・再解決は行いません。

### 処理上限と取消

| 項目 | 初期上限 |
|---|---|
| 接続先／試行／同時ソケット | 1／1／1 |
| DNS応答 | 8件 |
| DNS／TCP／プロトコル／全体 | 5／3／5／15秒 |
| プロトコルソケットの受信／送信 | 512 KiB／64 KiB |
| SSHバナー／暗号化前のフレーム全体 | 8 KiB／256 KiB |

通信量はプロトコルソケットから渡されたバイト数で、OSのDNS通信やTCPの付加情報・再送は含みません。\
取消時は接続を閉じますが、OSがすでに始めた名前解決は止まらない場合があります。\
未対応・過大な入力を黙って検査完了にはしません。

### 保存するファイルと終了コード

| コマンド | JSON | 既定の保存先 |
|---|---|---|
| `probe tls` | `probe.tls.v1.json` | `./pqc-probe/tls` |
| `probe ssh` | `probe.ssh-offers.v1.json` | `./pqc-probe/ssh` |
| `probe ssh-kex` | `probe.ssh-kex.v1.json` | `./pqc-probe/ssh-kex` |

いずれも `report.html`・`report.md` を併せて出力します。\
SSH鍵交換のHTMLは結果と理由を先に示し、技術情報は閉じた状態にします。\
JSON仕様は `schemas/probe-ssh-kex-v1.schema.json` を参照してください。\
過去の出力と混同しないよう、新しい保存先を指定します。\
`--lang ja` は人間向け文面だけを変え、静的スキャンの6出力や `scan.inventory.v1.json` は置き換えません。\
既知の秘密情報らしい構文は全出力でマスクし、`redaction_applied` で元の文字列の省略を示します。

| 終了コード | 意味 |
|---|---|
| 0 | 要求した観測が完了。安全性の保証ではありません |
| 1 | 準備・出力のエラー |
| 3 | 拒否・失敗・部分成功・取消・未対応 |

既存 `scan` の終了コード0／1／2／3は変わりません。
