# TLS・SSH接続先の明示的な診断

[English](PROBING.md) · [README](https://github.com/wakaken/pqc-scan/blob/develop/README.ja.md)

v0.2.0のTLS・SSH提示方式・SSH KEXは、いずれも実験的機能です。配布する静的版には `probe` コマンドを含みません。probe同梱版は配布・導入の技術検証を終えていますが、公開前の確認が残っています。[配布状況](DISTRIBUTION.ja.md#release-status)を参照してください。

管理者から検査の許可を得たホスト・ポートだけを指定してください。
`probe` は指定先と通信します。リポジトリの `scan` とレポート生成はローカルで完結し、ソース内のURL、証明書のSAN、所見を根拠に自動接続することはありません。

## 任意のコマンドを有効にする

既定のインストールは静的スキャン用です。固定されたRustツールチェーンで、必要な診断機能を付けてビルドします。

```bash
cargo install --locked --path crates/pqc_scan_cli --features probe-tls,probe-ssh
```

バイナリの配布対象環境はApple SiliconのmacOSです。Linux CIでも隔離環境でプロトコルとOpenSSHを検証しますが、Linux版バイナリや他のOS・アーキテクチャーの配布対応を意味しません。
TLS機能では暗号プロバイダーのネイティブビルドが加わります。静的スキャンだけのビルド・テストには不要で、AIサービスも使いません。

## TLS

```bash
pqc-scan probe tls service.example --port 443 --out-dir /path/to/new-tls-report
```

例のホスト名を許可済みの接続先へ置き換えてください。ポート指定は必須です。
TLS1.2・1.3の新しいハンドシェイクを1回行い、実際に選ばれた版、暗号スイート、鍵共有グループと、上限内で取得した公開証明書の情報を記録します。クライアント側の設定も残します。
アプリケーション要求、クライアント資格情報、セッション再開、0-RTT、鍵ログは使いません。TLS1.3のスイート名だけで、古典方式かハイブリッド方式かを判断することもありません。

固定したMozilla系ルート証明書を使って検証します。ローカルの公開CAへ置き換える例です。

```bash
pqc-scan probe tls 127.0.0.1 --port 8443 --allow-cidr 127.0.0.1/32 --server-name localhost --ca-file /path/to/public-ca.pem --out-dir /path/to/new-local-tls-report
```

`--ca-file` はルート証明書一覧を置き換えます。最大16個・合計256 KiBの公開証明書PEMだけを受け付け、秘密鍵やパスワードは入力しません。
信頼チェーン、名前、有効期間の通常検証は必須です。DNS名の検証対象はSNIにも使い、IPアドレスの検証ではSNIを送りません。`--server-name` で実際の接続先を変更することはできません。
このモードはOS固有の信頼制約や失効確認を提供しません。

内部APIから値が得られても、検証失敗後に「検証済みの交渉結果」として出力することはありません。
クライアント認証の要求は未対応です。証明書の収集上限は16個・256 KiBで、TLSライブラリ内部の小さなメッセージ上限に先に達する場合もあります。
失敗や上限到達は検査の不完全さを示し、サーバーのPQC非対応や危険性を断定するものではありません。

## SSHの提示方式

```bash
pqc-scan probe ssh service.example --port 22 --out-dir /path/to/new-ssh-report
```

識別文字列とKEXINITを交換し、相手が示す10種類の名前リストと拡張マーカーを順序どおり記録して、鍵交換の実行前に接続を閉じます。
service・userauth・channelの要求は送らず、`none` 認証も行いません。ユーザー名、agent、秘密鍵、SSH設定、システムのSSHコマンドは使いません。
診断クライアントの提案も記録しますが、そこに並べた暗号方式を実装しているという意味ではありません。

結果は**未認証の提示情報**です。選ばれた方式、検証済みホスト鍵、セッションの完了、サーバー全体の移行状況を証明しません。
バナーの版は相手の申告で、不明な識別子は不明のまま残します。

## 接続許可・上限・出力

既定では公開unicastを許可します。内部・ループバック・特殊用途のunicastには `--allow-cidr` が必要です。未指定アドレス、multicast、限定broadcastは許可できません。
mapped IPv6を含む全DNS応答を検査し、拒否対象が混在すれば接続しません。検証したソケットアドレスを固定し、実際のpeerも照合します。
proxy、redirect、設定ファイルによる展開、アドレスの再試行・再解決は行いません。

| 項目 | 初期上限 |
|---|---|
| 接続先／試行／同時ソケット | 1／1／1 |
| DNS応答 | 8件 |
| DNS／TCP／プロトコル／全体 | 5／3／5／15秒 |
| プロトコルソケットの受信／送信 | 512 KiB／64 KiB |
| SSHバナー／暗号化前のフレーム全体 | 8 KiB／256 KiB |

通信量はプロトコルソケットから渡されたバイト数で、OSのDNS通信やTCPの付加情報・再送は含みません。
取消時はソケットを閉じ、名前解決の子プロセスを回収します。OSサービスがすでに始めた名前解決の処理は、そのプロセスの管理範囲外です。
未対応・過大な入力を黙って検査完了にはしません。

TLSは `probe.tls.v1.json`、SSHは `probe.ssh-offers.v1.json` と、それぞれ `report.html`・`report.md` を出力します。
既定の保存先は `./pqc-probe/tls`・`./pqc-probe/ssh` です。過去の出力との混同を避けるため、新しい保存先を指定してください。
`--lang ja` で変わるのは人間向け文面だけです。静的スキャンの6出力や `scan.inventory.v1.json` は置き換えません。
既知の秘密情報らしい構文は全出力でマスクし、`redaction_applied` で元の文字列を省略したことを示します。

終了コード0は要求した観測の完了で、安全性の保証ではありません。1は準備・出力のエラー、3は拒否・失敗・部分成功・取消・未対応です。
既存 `scan` の終了コード0／1／2／3は変わりません。

## SSHハイブリッド鍵交換と接続先の確認（実験的機能）

この検査には、別の任意機能を有効にしてインストールします。

```sh
cargo install --locked --path crates/pqc_scan_cli --features probe-ssh-kex
pqc-scan probe ssh-kex service.example --port 22 --host-key-file /path/to/trusted-host.pub --lang ja --out-dir /path/to/new-ssh-kex-report
```

指定するのは、管理者などから別の信頼できる経路で入手した、OpenSSH形式の
**Ed25519ホスト公開鍵**1つです。今回明示した接続先の照合に使います。
未検証の接続先から取得した鍵を、そのまま信頼してはいけません。
秘密鍵、ホスト証明書、known_hosts、普段のSSH設定やagentは使いません。
公開鍵ファイルは4096バイトまでで、名前解決・接続の前に検証します。
Unixではシンボリックリンクや通常ファイル以外の入力も拒否します。

提示する方式は `mlkem768x25519-sha256`（ML-KEM768＋X25519のハイブリッド）と
ホスト署名の `ssh-ed25519` に固定します。従来方式だけの鍵交換へは切り替えません。
ライブラリが鍵交換署名を検証し、指定した公開鍵との一致と初回鍵交換の成立を
確認して切断します。
認証サービス要求、ユーザー名、パスワード、`none` 認証、ログイン、チャネル、リモートコマンドは送りません。
ホスト認証は従来方式のEd25519なので、ホスト署名のPQC対応や移行完了は意味しません。

ライブラリはアプリケーション側の公開鍵照合より先にNEWKEYSを送る場合があり、照合が後から不一致となる場合も同じです。不一致を検証成功として出力することはありません。`user_authentication_attempted: false` は認証を行わないクライアントの動作を示す値で、接続ごとのパケット観測値ではありません。

1試行、接続先の固定、アドレス許可、名前解決・時間・通信量・取消の制限は上記と共通です。
明示的な通信のため、接続先に記録される場合があります。不一致・未知の鍵は拒否します。
失敗や方式の不一致だけで、サーバー全体がPQC非対応だとは断定しません。

出力は独立した `probe.ssh-kex.v1.json` と `report.html`・`report.md` です。
既定の保存先は `./pqc-probe/ssh-kex`、JSON仕様は
`schemas/probe-ssh-kex-v1.schema.json` に定義しています。
失敗・未完了では、検証済みの方式を記録しません。
HTMLは結果と理由を先に示し、技術情報は閉じた状態にします。
既存の `probe ssh` は提示方式の収集のままで、従来の出力形式も維持します。
全コマンドが必要なら `probe-tls,probe-ssh,probe-ssh-kex` を有効にしてください。
`static`はprobeなし、`combined-probes`はTLS・SSH提示方式、`all-probes`はそれらとSSH KEXを含みます。v0.2候補では3構成の作成と導入を検証済みですが、probe同梱版の公開承認とは別です。
