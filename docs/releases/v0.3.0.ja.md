# v0.3.0

[English](v0.3.0.md) · [導入と配布](../user/DISTRIBUTION.ja.md)

macOS Apple Silicon（`aarch64-apple-darwin`）向けの静的版です。
維持者は2026年11月17日に、記載した評価範囲と品質上の制約を踏まえて製品を受け入れ、
最終ホスト型ビルドの来歴検証を条件に静的版の公開を承認しました。
Releaseには対象のソースコミットと配布物の識別情報を記録します。
公開済みの配布物は[GitHub Releases](https://github.com/wakaken/pqc-scan/releases)で確認してください。
準備物の保存だけでは公開済みとは扱いません。過去の[v0.2.0のノート](v0.2.0.ja.md)は保持しています。

## 変更点

- Unixのレポート出力では、ディレクトリをリンクをたどらずに開き、非公開の一時ファイルを
  用意してから差し替えます。既存のリンクや通常ファイル以外は拒否し、外部のハードリンク先を
  切り詰めません。新しい出力はモード0600（umaskの適用あり）で、以前のinodeの権限・ACL・
  拡張属性は引き継ぎません。レポート一式を一つの処理として確定する方式ではなく、
  第三者が出力先を書き換えられる場合の改変・削除も防ぎ切れません。Unix以外への出力は未対応です。
- RustのRSA／JWT依存は、Cargo名`rsa`・`jsonwebtoken`との完全一致で判定し、
  `universal-hash`のような名前を除外します。依存関係の棚卸しは、RSAの実利用の証明とは別です。
- Pythonの明示的なPQC importは、`from `の後のモジュールから位置を示します。
  正規表現ルールが`scope: config`と完全一致し、空白を除いた後も文字が残る場合は、
  先頭の空白を位置・根拠から除きます。すべての設定ファイルに適用する処理ではありません。
- 既定の`TLS_VERSION_1_0`では方式名そのものの位置を示し、区切り文字を共有する
  隣接参照も検出します。変更した独自パターン・scopeや別のIDには通常の照合を適用します。
  TLS名の参照は、実際の交渉結果や有効な設定を証明するものではありません。
- Javaの`RSAKeyGenParameterSpec`コンストラクタを残りの処理量の上限内で検査します。
  拒否したMaven依存座標が前の正常な宣言の注記を変える問題と、ASN.1パラメータの型を
  確認せずOID・曲線・鍵長の根拠にする問題も修正しました。
- ルールと重要な分岐の個別評価、互換性の確認、ソースに対応付けたCIの証拠を追加しました。
  汎用隔離suiteの読取り専用の出力先への書込み問題は修正・別途検証済みですが、ホスト型の
  `protocols`は停止中です。CIのセルフスキャンは製品ソース・Cargo入力・同梱ルールに範囲を絞り、
  確認済みの参照と要確認の報告を分けます。

## 互換性

製品バージョンは0.3.0です。出力形式はInventory v1、SARIF 2.1.0、CycloneDX 1.7を
維持し、既定の6ファイルの名前も変わりません。棚卸し・評価・診断情報・CycloneDX出力は、
引き続き明示的な指定が必要です。参照位置の補正でリスク・信頼度の方針は変えません。

所見IDの安定性は、同じバイナリ・ルール・選択入力・設定と同じ相対パスで、同じ所見を
得た場合の性質です。版をまたぐ位置・根拠・属性の補正や検出の追加では、計算方式が同じでも
値・件数・所見ID・観測ID・資産IDが変わる場合があります。旧IDだけで全所見を対応付けないでください。
証明書のNULLパラメータでは`parameters_oid`を出力しません。空文字列を必須とせず、
任意のメタデータ項目として扱ってください。

バイナリと対応するルールを一組で保管し、ソースコミットを記録します。更新時は新しい
ディレクトリへ展開し、差し戻し用に以前の検証済み一式を残してください。
公開済みv0.2.0のアーカイブに、この候補の変更は含まれません。

## 対応範囲・証拠・制約

正式なバイナリの準備範囲は、macOS Apple Siliconの静的スキャンです。
TLS・SSHはソースビルドで有効にする任意の実験的機能です。`network`版は依存パッケージ
4件の通知文確認と、構成ごとの来歴・公開の確認を残して保留しています。
Linuxでのテスト成功はLinux版の公開を意味しません。0.2.x・0.3.xの各系列で最新の検証済み版を
可能な範囲で保守します。SLAや旧版への修正適用は保証しません。

[候補の評価](https://github.com/wakaken/pqc-scan/blob/d20a1f1872d8527d90dc3832a0d8b1b2284405b7/docs/releases/static-candidate-20261117/AUDIT-FIXES.md)と
[個別評価](https://github.com/wakaken/pqc-scan/blob/d20a1f1872d8527d90dc3832a0d8b1b2284405b7/docs/releases/static-candidate-20261117/QUALITY-COMPLETION.md)には、
対象ソース・方法・制約を記録しています。最終ソースの
[CI](https://github.com/wakaken/pqc-scan/actions/runs/44035459748)や、ローカルの静的版アーカイブ・
導入の確認は技術的な証拠で、公開の許可ではありません。チェックサムはマニフェストからの
変更を検出するもので、信頼できる署名者を証明しません。ローカルアーカイブには、
ホスト型の来歴証明は付きません。

ソースを確認して作ったルールの対照例は、独立した母集団の精度や、あらゆる暗号処理の安全性を
保証するものではありません。静的範囲の9方向は、不変条件を評価していますが未観測のままです。
LLVMの補助診断の失敗と、追加監査のファジングがPartialで終了した記録も維持し、
成功には置き換えていません。同一ホスト内の独立したビルド先での一致は、異なるホスト間の
再現性を保証しません。誤検出・見逃し・未対応入力・不完全な検査は残り得ます。
所見0件だけでは、安全性やPQC移行完了は確認できません。
