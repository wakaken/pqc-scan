# v0.3.0

[日本語](v0.3.0.ja.md) · [Installation](../user/DISTRIBUTION.md)

This version targets static scanning on macOS Apple Silicon
(`aarch64-apple-darwin`). The maintainer accepted the documented bounded quality
limits and authorized static publication on 2026-11-17, subject to final hosted
build-provenance verification. The source commit and matching archive identity
must be recorded with the Release. Check [GitHub Releases](https://github.com/wakaken/pqc-scan/releases)
for published assets; preparation artifacts alone do not establish publication.
Historical [v0.2.0 notes](v0.2.0.md) remain unchanged.

## Changes

- Redesign HTML reports with compact summaries, severity distribution, grouped
  findings and expandable evidence. Add search/filters, a count-bearing file tree,
  independent panel visibility, responsive layouts and print support.
- Add English/Japanese and light/dark selectors, browser-local timestamps and an
  offline companion rule guide. Clarify certificate-expiry guidance while keeping
  detection criteria and machine-readable findings unchanged.
- Add `pqc-scan serve`: a loopback-only folder picker that scans a selected local
  project with the existing static pipeline and opens its report. This command is
  included in the default `static` build; it does not require probe features.
  See the bundled [web scanning guide](../user/SCANNING.md#local-web-scanning).
- Protect Unix report destinations with no-follow directory traversal, exclusive
  staged writes and atomic replacement. Existing symlinks/nonregular destinations
  are rejected; an external hard-linked file is not truncated. New outputs use
  mode 0600, subject to umask. Replacement does not preserve old inode permissions,
  ACLs or extended attributes. A report set is not one transaction; hostile
  concurrent writers can still alter/remove reports. Non-Unix output is unsupported.
- Match Rust RSA/JWT dependencies by the exact Cargo names `rsa` and
  `jsonwebtoken`, excluding names such as `universal-hash`; dependency inventory
  remains separate from proof of actual RSA use.
- Locate explicit Python PQC imports at the module after `from `. For regex
  rules with exactly `scope: config`, remove leading layout only when a
  non-whitespace match remains. This does not apply to every configuration file.
- Report token-only positions for the exact default `TLS_VERSION_1_0` rule and
  preserve adjacent references sharing a delimiter. Modified custom patterns,
  scopes and unrelated IDs keep generic matching. TLS names remain references,
  not negotiated protocol or effective-configuration evidence.
- Inspect explicit Java `RSAKeyGenParameterSpec` constructors within residual
  budgets; prevent rejected Maven coordinates from relabelling an earlier valid
  dependency; check ASN.1 parameter types before deriving OID/curve/key-size facts.
- Add individual rule and important-branch assessments, compatibility controls
  and source-bound CI evidence. The generic isolated suite's read-only output
  failure is corrected and separately verified; hosted `protocols` remains paused.
  CI self-scan limits its input to product sources, Cargo inputs and shipped rules,
  and separates exact reviewed references from results requiring review.

## Compatibility

The product version is 0.3.0; format versions remain Inventory v1, SARIF 2.1.0
and CycloneDX 1.7. The six original report filenames remain unchanged. HTML generation also writes
`report.rules.html`; keep it beside `report.html` for the rule links. `--format all`
therefore produces seven files. Optional
inventory, assessment, diagnostic and CycloneDX outputs still require explicit
options. Risk/confidence policy is not changed by reference-position corrections.

ID stability applies to identical findings with the same binary, rules, selected
input and settings at the same relative paths. Between versions, corrected
locations/evidence, additional references and corrected attributes can change
values, counts and finding/observation/asset IDs without changing the identity
algorithm. Do not join all version-to-version findings solely by an old ID.
NULL certificate parameters have no `parameters_oid` metadata entry; consumers
must treat it as optional rather than requiring an empty string.

Keep each binary with its matching rule pack and record its source commit.
Unpack into a new directory and retain the previous verified bundle for rollback.
The published v0.2.0 archive does not contain these candidate changes.

## Support, evidence and limits

Formal binary preparation covers static scanning on macOS Apple Silicon only.
TLS/SSH commands remain optional experimental source-build features. `network`
publication remains held for four dependency notice reviews and separate
provenance/publication checks; Linux tests do not establish a Linux release.
The latest verified snapshots in both 0.2.x and 0.3.x receive best-effort
maintenance. No SLA or older-version backport guarantee is declared.

The [candidate evaluation](https://github.com/wakaken/pqc-scan/blob/d20a1f1872d8527d90dc3832a0d8b1b2284405b7/docs/releases/static-candidate-20261117/AUDIT-FIXES.md)
and [individual assessments](https://github.com/wakaken/pqc-scan/blob/d20a1f1872d8527d90dc3832a0d8b1b2284405b7/docs/releases/static-candidate-20261117/QUALITY-COMPLETION.md)
identify their source, methods and limits. Final-source
[CI](https://github.com/wakaken/pqc-scan/actions/runs/44035459748) and local static
archive/clean-install checks are technical evidence, not release authorization.
Checksums detect changes relative to their manifests; they do not establish a
trusted signer. A local archive has no hosted attestation by default.

Nominal source-aware rule controls are not independent population accuracy or
universal cryptographic assurance. Nine static invariant outcome directions remain
unobserved. Auxiliary LLVM diagnostic failure and the additional audit fuzz
campaign's Partial result remain recorded; neither is silently treated as success.
Same-host independent build roots do not establish cross-host reproducibility.
False positives, missed references, unsupported inputs and incomplete inspection
remain possible. Zero findings do not prove safety or completed PQC migration.
