# v0.4.0

[Installation](../user/DISTRIBUTION.md) · [日本語の利用ガイド](../user/DISTRIBUTION.ja.md)

Release scope: static/default and network macOS Apple Silicon
(`aarch64-apple-darwin`). The maintainer authorized publication on 2026-11-24,
subject to final-source distribution, hosted CI and build-provenance checks.
Published assets are listed in [GitHub Releases](https://github.com/wakaken/pqc-scan/releases).
TLS/SSH diagnostics are supported v0.4 features within this platform scope.

## Changes

- Provide a `network` archive with TLS, SSH advertisement and pinned
  hybrid SSH key exchange commands. Preserve explicit-target authorization, trust
  verification, bounded traffic/time and no-authentication behavior. Both archive
  variants receive exact-source hosted build attestations.

- Add offline `assess` for saved Inventory v1, TLS v1, SSH offers v1 and SSH KEX v1
  evidence. Keep observed technical roles separate from declared organization/use
  context, urgency, information sufficiency, migration readiness and next action.
- Add `context-template` for explicit target selection and validated context
  generation without manually copying digests or IDs. Context is bound to the
  exact saved input, including its bytes; reformatted input requires rebinding.
- Add opt-in `serve --migration` for purpose/usage input, saved context import,
  review and reassessment using the same evaluator without rescanning. Generated
  HTML, input JSON and assessment JSON have separate save actions.
  Evaluation uses creation time by default, while explicit historical times are
  preserved with warnings for later declarations. Input JSON saving reports
  progress/failure, supports retry and retains exact bytes for reassessment.
- Organize migration HTML around actions and conditions for proceeding. Eligible
  migration plans show current-use discovery, compatibility testing and staged
  rollout. Investigations, monitoring and exclusions show their own checks.
  Urgent investigations remain visible; remaining checks fold only when a
  use-specific workflow exists. Schedule fields distinguish start-by from
  migration deadline; goal month remains planning information.
- Group equivalent detections by location, retain matching rules/methods in
  details, wrap long paths and keep location search. Remove work-list filters
  and repeated trailing checklists/ledgers. Same-job reports can link back to
  original scan findings; standalone assessment HTML preserves its own evidence.
- Support sequential multi-folder browser scans and named per-folder results and
  session history, with separate scan-report and migration-review entrypoints.
- Add optional test-code exclusion and root `.pqcignore` selection. Tests remain
  included by default. Preserve explicit scope and incomplete-inspection details.
- Make the primary per-file selection limit configurable with `--max-file-size-mib`
  and the folder picker (1–64 MiB, default 2 MiB); detector and secondary-read
  budgets remain separate.
- Add `API_RUBY_OPENSSL_CIPHER` and `API_RUST_OPENSSL_TLS`, bringing the built-in
  rule set to 125 rules. Keep matching rules with the binary.
- Extend bounded JS/TS constant-import/JWT-wrapper tracking, Ruby cipher and
  gemspec references, and Rust OpenSSL TLS references. These retain source facts
  and unresolved/partial states rather than inferring runtime behavior; see
  [coverage](../user/COVERAGE.md#source-facts).
- Improve bounded source-reference/parameter handling, diagnostics and human
  finding aggregation. A reference remains distinct from deployed cryptography.
- Bundle the saved-evidence guides and exact-revision upstream notices for
  `uuid-simd 0.8.0` and `vsimd 0.8.0` without weakening packaging guards.

## Compatibility

Product version becomes `0.4.0`; Inventory v1, migration context/assessment v1,
SARIF 2.1.0, CycloneDX formats and existing scan filenames remain unchanged.
`assess` writes `migration.assessment.html`, `migration.assessment.md` and
`migration.assessment.v1.json`. Optional commands/features do not change ordinary
scan defaults. Local `migration-review-v1` and the organization-aware saved-input
assessment remain distinct paths.

New optional context fields retain adopted v1 validation, exact-input binding,
claim provenance and freshness. Goal month does not set a deadline. Omitted
expiry remains unknown validity; declared readiness is not verified deployment.
Test-only usage alone does not suppress urgent known classical concerns; an
active explicit outside-scope declaration takes precedence and retains facts
and reassessment conditions.

Human HTML/Markdown can aggregate equivalent findings while machine scan JSON
retains rule-level records. Version-to-version position/evidence corrections,
additional detection and changed selection can change counts and IDs. Compare
binary/source, rules and selection alongside IDs. Keep each binary with matching
rules/notices; extract into a new directory and retain the previous verified
bundle for rollback. Output remains Unix-only with existing symlink/private
staging and per-file atomic replacement protections.

## Evidence and support boundaries

Tasks [071](../../tasks/071/TASK-071-RESULTS.md),
[072](../../tasks/072/TASK-072-RESULTS.md) and
[075](../../tasks/075/TASK-075-CURRENT-RESULTS.md) record acceptance within the
explicit 2026-11-19 limited scope. The synthetic study covers technical facts,
adopted specification and fixed-condition repeatability: 24 cases/12 pairs,
48 CLI runs, 222/222 eligible technical properties and 507/507 specification
properties agreeing, with 56 unconfirmed statements excluded. These are bounded
historical observations, not population accuracy or a new final-source run.

Human practical usefulness, workload, inter-rater agreement, independent human
expert validation and numerical-score validity/superiority/adoption remain
unmeasured. The original 96 human judgments remain unexecuted. Do not interpret
amended task completion or a passing CI run as evidence for those dimensions.
False positives, missed references and incomplete inspection remain possible;
zero findings do not establish safety or completed PQC migration.

Static/default and network macOS Apple Silicon are in the v0.4 distribution scope.
The maintainer accepted best-effort v0.4 maintenance without an SLA or backport
guarantee. The existing maintenance disposition for verified 0.2.x/0.3.x remains
unchanged. No Linux, other binary platform or crates.io support is introduced. Unix SIGINT
handling uses a signal-hook worker calling the existing cancellation token/socket
shutdown path; non-Unix retains ctrlc. The selected macOS network graph no longer
contains the four historical Objective-C notice holds; their original records remain
review-required for any graph that selects them. Hosted `protocols` remains disabled;
its skipped status is not a protocol pass. Identical archives from the same
binary/source/tools do not establish cross-host reproducible builds.

## Maintainer acceptance — 2026-11-24

The maintainer explicitly accepted publication of the static and network variants
based on candidate `58a44cc95d829593237bf8ad069afe65a9360b5f`, with the requested
README edits synchronized into English before publication. The final source is a
documentation-only descendant of that verified candidate; executable source,
dependencies, schemas, rules and workflows are unchanged. Final archives and
attestations are rebuilt and verified against the actual tagged commit.

The chrono 0.4.44 maintenance warning
[RUSTSEC-2026-0543](https://rustsec.org/advisories/RUSTSEC-2026-0543.html) is accepted
as a **v0.4-only exception through 2027-01-23**. Both variants retain the warning;
no audit ignore or suppression is added. Recheck advisories before publication
and re-evaluate earlier if a concrete vulnerability is reported. No patched
version was available in the recorded audit. This maintenance exception is not
a claim that the dependency or product is vulnerability-free.

The original unaccepted audit results and historical readiness checkpoints remain
unchanged. The [network readiness record](https://github.com/wakaken/pqc-scan/blob/v0.4.0/docs/releases/v0.4-network-readiness-20261124/README.md)
records the affected use and the subsequent maintainer decision. Publication uses
the final verified commit and archive digests, with best-effort maintenance and
no SLA/backport guarantee. The authorization does not imply merging develop or
adding another platform.
